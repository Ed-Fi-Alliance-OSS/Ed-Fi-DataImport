## Task 4: Replace Rijndael256 with BCL AES

**Goal:** Re-implement `DataImport.Common/Encryption.cs` using `System.Security.Cryptography` so that it produces byte-for-byte identical output to the `RijndaelEtM` class from the `Rijndael256` library. Existing encrypted values in the database must continue to decrypt correctly.

**Files:**
- Modify: `DataImport.Common/Encryption.cs`

**Background:** The `Rijndael256` library's `RijndaelEtM` class implements Encrypt-then-MAC (EtM) using:
- AES-256-CBC for encryption
- PBKDF2 (`Rfc2898DeriveBytes`) with HMAC-SHA512 for key derivation
- HMAC-SHA512 for the authentication tag
- Output wire format: `Base64(hmac[64] + salt[32] + iv[16] + ciphertext[...])`

Before implementing, **verify** the exact wire format by reading the [Rijndael256 source on GitHub](https://github.com/PathosDev/Rijndael256). The key parameters to confirm: salt length, PBKDF2 iteration count, key derivation split (encryption key bytes vs. HMAC key bytes), and MAC coverage (whether MAC is over IV+ciphertext or only ciphertext).

- [ ] **Step 1: Read the Rijndael256 source code to confirm wire format**

  Browse to the `RijndaelEtM.cs` source in the `Rijndael256` repository and record:
  - Salt length in bytes
  - PBKDF2 iteration count
  - How the derived bytes are split into AES key and HMAC key
  - Exactly what the HMAC covers
  - The byte layout of the output buffer

- [ ] **Step 2: Write a failing test that documents expected round-trip behavior**

- [ ] **Step 4: Rewrite `DataImport.Common/Encryption.cs`**

  Replace the file with a BCL implementation that replicates the exact EtM wire format confirmed in Step 1. The public API (`Encrypt(string, string)` and `Decrypt(string, string)`) must remain identical — no signature changes.

  **Parameter name note:** The original `Decrypt` signature has a typo — `ciphertText` (extra `t`). The BCL replacement corrects this to `cipherText`. This is safe: all call sites in the codebase pass the argument positionally, so no callers are affected. The diff will show this spelling fix; it is intentional.

  Template (fill in exact parameters from Step 1):

  ```csharp
  // SPDX-License-Identifier: Apache-2.0
  // Licensed to the Ed-Fi Alliance under one or more agreements.
  // The Ed-Fi Alliance licenses this file to you under the Apache License, Version 2.0.
  // See the LICENSE and NOTICES files in the project root for more information.

  using System;
  using System.Security.Cryptography;
  using System.Text;

  namespace DataImport.Common
  {
      public static class Encryption
      {
          // These constants must match the Rijndael256 RijndaelEtM implementation exactly.
          // Verify all values against https://github.com/PathosDev/Rijndael256 before finalizing.
          private const int SaltBytes = 32;         // Verify against source
          private const int Iterations = 10000;     // Verify against source
          private const int AesKeyBytes = 32;       // AES-256
          private const int HmacKeyBytes = 64;      // HMAC-SHA512
          private const int IvBytes = 16;           // AES block size
          private const int HmacBytes = 64;         // SHA-512 output

          /// <summary>
          /// Encrypts plaintext using the Encrypt-then-MAC (EtM) mode via AES-256-CBC
          /// with a password-derived HMAC SHA-512 salt. A random 128-bit Initialization
          /// Vector is generated for the cipher.
          /// </summary>
          public static string Encrypt(string plainText, string encryptionKey)
          {
              var keyBytes = Encoding.UTF8.GetBytes(encryptionKey);
              var salt = RandomNumberGenerator.GetBytes(SaltBytes);

              DeriveKeys(keyBytes, salt, out var aesKey, out var hmacKey);

              using var aes = Aes.Create();
              aes.Key = aesKey;
              aes.GenerateIV();
              var iv = aes.IV;

              var plainBytes = Encoding.UTF8.GetBytes(plainText);
              var cipherBytes = aes.EncryptCbc(plainBytes, iv);

              // MAC covers IV + ciphertext (verify this order against Rijndael256 source)
              var macInput = new byte[iv.Length + cipherBytes.Length];
              Buffer.BlockCopy(iv, 0, macInput, 0, iv.Length);
              Buffer.BlockCopy(cipherBytes, 0, macInput, iv.Length, cipherBytes.Length);

              using var hmac = new HMACSHA512(hmacKey);
              var mac = hmac.ComputeHash(macInput);

              // Wire format: hmac[64] + salt[32] + iv[16] + ciphertext
              // Verify this layout against Rijndael256 source
              var output = new byte[HmacBytes + SaltBytes + IvBytes + cipherBytes.Length];
              Buffer.BlockCopy(mac, 0, output, 0, HmacBytes);
              Buffer.BlockCopy(salt, 0, output, HmacBytes, SaltBytes);
              Buffer.BlockCopy(iv, 0, output, HmacBytes + SaltBytes, IvBytes);
              Buffer.BlockCopy(cipherBytes, 0, output, HmacBytes + SaltBytes + IvBytes, cipherBytes.Length);

              return Convert.ToBase64String(output);
          }

          /// <summary>
          /// Decrypts EtM ciphertext using AES-256-CBC with a password-derived HMAC SHA-512 salt.
          /// </summary>
          public static string Decrypt(string cipherText, string encryptionKey)
          {
              var keyBytes = Encoding.UTF8.GetBytes(encryptionKey);
              var input = Convert.FromBase64String(cipherText);

              var mac = new byte[HmacBytes];
              var salt = new byte[SaltBytes];
              var iv = new byte[IvBytes];
              var cipherBytes = new byte[input.Length - HmacBytes - SaltBytes - IvBytes];

              Buffer.BlockCopy(input, 0, mac, 0, HmacBytes);
              Buffer.BlockCopy(input, HmacBytes, salt, 0, SaltBytes);
              Buffer.BlockCopy(input, HmacBytes + SaltBytes, iv, 0, IvBytes);
              Buffer.BlockCopy(input, HmacBytes + SaltBytes + IvBytes, cipherBytes, 0, cipherBytes.Length);

              DeriveKeys(keyBytes, salt, out var aesKey, out var hmacKey);

              // Verify MAC before decrypting
              var macInput = new byte[IvBytes + cipherBytes.Length];
              Buffer.BlockCopy(iv, 0, macInput, 0, IvBytes);
              Buffer.BlockCopy(cipherBytes, 0, macInput, IvBytes, cipherBytes.Length);

              using var hmac = new HMACSHA512(hmacKey);
              var expectedMac = hmac.ComputeHash(macInput);
              if (!CryptographicOperations.FixedTimeEquals(mac, expectedMac))
                  throw new CryptographicException("MAC verification failed.");

              using var aes = Aes.Create();
              aes.Key = aesKey;
              var plainBytes = aes.DecryptCbc(cipherBytes, iv);
              return Encoding.UTF8.GetString(plainBytes);
          }

          private static void DeriveKeys(byte[] keyBytes, byte[] salt, out byte[] aesKey, out byte[] hmacKey)
          {
              // Total derived bytes = AES key (32) + HMAC key (64)
              using var kdf = new Rfc2898DeriveBytes(keyBytes, salt, Iterations, HashAlgorithmName.SHA512);
              var derived = kdf.GetBytes(AesKeyBytes + HmacKeyBytes);
              aesKey = new byte[AesKeyBytes];
              hmacKey = new byte[HmacKeyBytes];
              Buffer.BlockCopy(derived, 0, aesKey, 0, AesKeyBytes);
              Buffer.BlockCopy(derived, AesKeyBytes, hmacKey, 0, HmacKeyBytes);
          }
      }
  }
  ```

  **Critical:** Verify every constant and byte-layout assumption against the Rijndael256 source before finalizing. Differences in iteration count, salt length, output layout, or MAC coverage will silently break decryption of existing data.
